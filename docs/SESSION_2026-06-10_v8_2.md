# Session 2026-06-10 (afternoon) — v8.2 train and eval

Second major session of v8.2 work. The morning session set up infra and produced
v8.1 (BA=0.510, failed because the training data lacked real pre/post-fix pairs).
This session built v8.2 on top of CVEFixes pre/post pairs, trained it, and
evaluated on three distributions to test generalisation. The model bit our home
benchmark hard but did not generalise to external SastBench at frontier-killer
levels.

## Goals coming in

1. Solve v8.1's Lesson 0 (no real pre/post pairs) using CVEFixes
2. Add anti-shortcut measures (pair length matching, MLP sanity check)
3. Pick an FP-reasoning teacher empirically (A/B between 6+ frontier models)
4. Train v8.2 on the new data
5. Evaluate on three distributions: in-domain mixed-FP, fresh CVE post-fix, SastBench
6. Decide v8.2's product readiness

## What got done

### Data layer

- Added `src/data_prep/prepare_cvefixes_triage.py` (later rewritten 3 times)
- Discovered `hitoshura25/cvefixes` HF dataset gives `vulnerable_code` AND

### Teacher A/B

- Wrote `scripts/teacher_smoke.py` — empirically compare candidate teacher LLMs

  rate, template-pattern rate, length
- First A/B attempted 6 models, several errored out (GPT-5+ rejects max_tokens,
  Sonnet "latest" alias not valid on our OR key)
- Fixed model IDs and the max_completion_tokens issue, then re-ran
- **Winner: Claude Haiku 4.5** (variance 0.997, specificity 1.0, template 0,
  $0.0009/call) over Opus 4.8, Sonnet 4.6, GPT-5.5/5.4/5.4-mini, DeepSeek-v4-pro
- Eyeball confirmed Haiku quality is equivalent to Opus 4.8 at 5x lower cost

### v8.2 data — three iterations

**Iteration v2.1 (post-fix only)**:
- FP = `fixed_code` of same CVE row
- Shortcut MLP: LogReg F1=0.69 → FAIL (FP code 1.78x longer than TP code)
- Wasted: $1.16 + 45 min

**Iteration v2.2 ("mixed FP" but I mis-coded it)**:
- Both FP sources still used `fixed_code` from CVEFixes
- Shortcut MLP: LogReg F1=0.69 — same fail because both sources had the
  post-fix length signature
- Wasted: $1.16 + 45 min

**Iteration v2.3 (real mixed = post-fix + misclassification)**:
- 20% FP = post-fix of same CVE (true differential signal)
- 80% FP = `vulnerable_code` of a DIFFERENT CVE with a different real CWE, but
  claimed as our CWE (misclassification simulation)
- **Critical lesson: simulated the fix with `simulate_misclass.py` BEFORE
  spending API credits** — confirmed TP/FP length ratio drops from 1.78 to 1.10
- Shortcut MLP: LogReg F1=0.50 (= random baseline for balanced 50/50) ✓
- Cost: $1.16, 45 min, but with confidence we wouldn't waste it

### Training v8.2

- Qwen2.5-Coder-7B-Instruct + LoRA r=16, alpha=32, 40.4M trainable (0.53%)
- 1794 train + 332 val pairs, 3 epochs, lr=1e-4 cosine, max_seq=2048
- save_steps=50, save_total_limit=8 (Lesson 8 from HISTORY)
- RunPod A6000 48GB, 42 min wall-clock, ~$0.33
- Final: train_loss=0.687, mean_token_accuracy=0.885
- Adapter pushed to HF `JJKennedy/vuln-llm-adapters/v8_2`

### Evaluation across three distributions

Ran v8.2 on three test sets to deliberately stress different parts of the
distribution:

1. **triage_test_balanced** (248 cases, 50/50, same FP mix as train)
2. **fresh_cves_60** (60 cases, 100% post-fix FPs — synthetic hand-crafted)
3. **SastBench-250** (250 cases from RivalSecurity public benchmark, real
   Semgrep findings on real repos, 35 TP + 215 FP)

For SastBench: wrote `src/data_prep/convert_sastbench_to_triage.py` — fetches
code from GitHub raw URLs using aiohttp concurrency 20 (~10 min for full 808
web-domain subset).

For mid-eval visibility: patched `src/eval/run_triage_eval.py` to write
`*_metrics.partial.json` every 20 examples (a permanent improvement).

## What we learned

### Learnings about model behaviour

1. **Overfitting is structural, not accidental.** v8.2 hit BA=0.82 on the
   distribution it was trained on (mixed-FP CVEFixes) and BA=0.47 on a
   slightly-different distribution (pure post-fix). The model memorised our
   training distribution rather than learning "is the SAST claim correct".

2. **Length-shortcut is not the only shortcut.** After per-pair length
   matching, LogReg still scored F1=0.85 (worse than no matching) because
   "// ... truncated for length normalisation" suffix became a new feature.
   Lesson: any marker you add can be learned.

3. **Post-fix and misclassification FPs need separate signals.** Training on
   80% misclass made the model great at "is this code matching the claimed CWE
   pattern?" but useless at "has the bug been patched in this code?". Both
   skills are needed in production.

4. **40M trainable params over 1.8k pairs is 22000:1 ratio**. With LoRA r=16
   we're massively overparameterised. r=8 (v7lite_r8 lesson) would have been
   better. We knew this and ignored it for v8.2.

### Learnings about workflow

5. **Smoke before pay.** Three full preps wasted $3+ before we built
   `simulate_misclass.py` that proves length distributions without a single
   API call. The cost of $0 sanity checks is ALWAYS less than the cost of
   full runs.

6. **One small mistake compounds**: I forgot to kill the first prep when the
   user cancelled the Bash tool. The nohup launcher detached from my session
   and kept running with the wrong teacher (GPT-4o instead of Haiku), burning
   $4 silently. Always kill the background process explicitly when restarting.

7. **Mid-eval partial dumps help debugging huge.** The patched
   `_dump_partial()` every 20 examples means we can see fresh_cves was going
   into paranoia after 20 cases without waiting the full 7 minutes.

8. **Frontier models on triage are NOT random in some cases.** smoke 10
   showed GPT-4o BA=0.875 on a tiny sample, but we knew from triage_100
   measurements that the same GPT-4o averages BA=0.50. Small-sample noise is
   real — smoke 10 is a sanity check, not a benchmark.

### Learnings about the product

9. **In-house benchmarks have home advantage.** v8.2 looks great on
   test_balanced (BA 0.82) but matches Sonnet 4.5 on SastBench (MCC 0.10).
   External validation matters more than internal.

10. **One adapter, three policies (calibration trick).** v5b lesson: sweep
    threshold on first-token logprobs gives free +0.05 F1. We have not yet
    applied this to v8.2 — likely worth +0.03-0.05 MCC on SastBench.

11. **Different FP types in production need different training mixes.** Real
    Semgrep output likely has BOTH post-fix-like FPs (modernised code with
    sanitisation) AND misclass FPs (wrong CWE). Our 20/80 split was too biased.

## What was confirmed

- **Lesson 0 from HISTORY is fixable**: real pre/post pairs from CVEFixes work
  for training the differential signal. v8.2 was 22 percentage points better
  than v8.1 on test_balanced.
- **Teacher quality matters less than ground truth.** Haiku 4.5 is 5x cheaper
  than Opus 4.8 but eyeball is equivalent for our use case.
- **Project-stratified split is mandatory.** We saw zero project leakage
  between train and any test set; the 0.47-0.55 generalisation gap is honest.
- **MCC is the right primary metric.** F1=0.27 on SastBench-250 sounded
  catastrophic; MCC=0.10 says "matches frontier mid-tier". They tell different
  stories on imbalanced sets.

## What was disproven

- **"Misclass-heavy training generalises well to real FPs"** — false. The
  fresh_cves and SastBench results show that misclass-trained model fails
  on post-fix-style FPs.
- **"More base model parameters (14B) would help"** — wrong assumption a user
  raised mid-session. The bottleneck is LoRA capacity over our train set, not
  base model size. 14B with the same LoRA r=16 on 1.8k pairs would have the
  same overfit problem.
- **"Length matching is enough to kill structural shortcut"** — wrong. Even
  with TP/FP length ratio = 1.0, LogReg still scored F1=0.87 because of
  comment density and keyword count differences. We needed to change the
  FP source (misclass), not just truncate.

## What's open / for v8.3

- **Train data needs distribution variety.** 50% misclass + 50% post-fix
  baseline, plus 10-20% synthetic adversarial FPs from teacher, plus
  CrossVul mix-in for OOD coverage.
- **LoRA r sweep**: re-run with r=4, 8, 16 to find OOD-optimal capacity.
- **Multi-CWE expansion**: current 12 web CWEs cover only 34% of SastBench
  CWEs. Add CWE-319 (Cleartext), CWE-1333 (ReDoS), CWE-95 (Eval Inj), CWE-134
  (Format), CWE-353, CWE-200.
- **Calibration sweep**: extract logprobs on val, find threshold maximising
  MCC on SastBench. Easy +0.03-0.05 win.
- **Sprint 2 evidence packet**: include file_path, function_start_line,
  function_end_line in TRIAGE prompt. Closer to SastBench's input format.
- **Adversarial augmentation**: rename identifiers, inject comments, vary
  whitespace, all preserving semantics. Reduces train-distribution memorisation.
