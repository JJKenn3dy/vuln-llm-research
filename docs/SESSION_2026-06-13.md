## TL;DR

- The model is "real but limited". On the trusted gold-core it TIES frontier on
  accuracy (AUC ~0.75) and wins on operating point (FAR 18% vs ~50%) + cost +
  ranking ability. It does NOT beat frontier on accuracy.
- Root cause of its limits found and proven: **v8.3.1 is blind to escaping.**
  On 20 matched CWE-79 vuln/safe pairs it called ALL 40 cases TRUE_POSITIVE
  (pair discrimination 0/20 vs GPT-5.3 20/20). It pattern-matches sink shape,
  does not read the actual data flow / escaping.
- This traces to the training data: 69% of TP rows have the sink outside the
  snippet, so the model never had the signal to learn escaping = the
  discriminator. The pile cannot be cheaply rescued.
- Pivot (Zakhar's idea, now backed by numbers): build CONTROLLED data where
  escaping is the discriminator and the sink is in-window. The controlled
  CWE-79 testbed is built + frontier-anchored and is both the diagnostic and
  the v8.4 training-signal template.
- v8.4 experiment is designed and PAUSED before the build+train step.

## v8.4 experiment design (ready to build)

Goal: decisive go/no-go on "can controlled data teach escaping-discrimination".

- TRAIN: procedural generator of self-contained CWE-79 pairs (untrusted source
  visible → sink visible → escaping the only difference), heavy diversity
  (sources × sinks × escape APIs × contexts × identifiers × languages) so no
  template can be memorized. ~300-500 pairs.
- TEST (held out): (a) the 20 hand-built pairs with mechanisms NOT in train,
  (b) frontier-clean subset of mined real pairs. Measures generalization
  synthetic→real, which also answers the "did it just memorize the template"
  worry.
- METRIC: pair discrimination, frontier-anchored (GPT-5.3 100% on hand-built).
  Success = climb from 0/20 toward frontier AND transfer to the real held-out.
- COST: generator is code (no GPU); train ~$3-4 + killer eval ~$0.5 on pod.
