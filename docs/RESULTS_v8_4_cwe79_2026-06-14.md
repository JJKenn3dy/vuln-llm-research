# v8.4-CWE79-exp1 results — synthetic-only does NOT transfer (2026-06-14)

Continue-trained from v8.3.1 on 135 filtered CyberNative XSS pairs (gentle LR
5e-5, 3 epochs, clean train loss 0.45→0.10). Evaluated on 3 held-out angles.
Adapter: /workspace/adapters/v8_4_cwe79. Pod: temp A40, terminated.

## The numbers

| Eval | metric | v8.3.1 | v8.4 |
|---|---|---|---|
| **controlled-20** (synthetic) | pair discrimination | 0/20 | **11/20** |
| controlled-20 | MCC / DR / FAR | 0.00 / 100% / 100% | 0.546 / 95% / 45% |
| **mined-real** (real-code transfer) | pair discrimination | — | **5/71 (7%)** |
| mined-real | DR / FAR | (paranoid TP) | 15% / 8% |
| **gold-core** (n=71, trusted) | MCC / DR / FAR | 0.447 / 64% / 18% | 0.313 / 14% / 0% |
| sastbench-250 | MCC / DR / FAR | 0.177 / ~89% / ~23% | 0.189 / 8.6% / 0.9% |

## What happened

**Positive (the proof):** the model demonstrably CAN learn escaping. Controlled
discrimination went 0/20 → 11/20, MCC 0 → 0.546. The architecture is not the
blocker — given the right signal, a 7B learns that escaping flips the verdict.

**Negative (the verdict):** it did NOT transfer to real code, and over-corrected.
- mined-real: only 5/71 pairs discriminate; **60/71 are now both=FP** — the model
  flipped from "everything is TP" (v8.3.1 paranoia) to "everything is FP" on real
  code. DR collapsed to 15%.
- gold-core: DR 64% → 14%, MCC 0.447 → 0.313. The over-correction hit the trusted
  core too, not just the transfer set.
- As a product this is WORSE than v8.3.1: it clears ~90% of everything and misses
  ~85% of real vulnerabilities. A scanner that misses real bugs is unusable.

**Mechanism:** the model learned synthetic CyberNative patterns (mechanism-
specific: the 9 failed controlled pairs are all the mechanisms it generalized
worst on), and continue-training on pure synthetic XSS shifted its whole prior
toward FP. On real, messy code it doesn't recognize the synthetic vuln shape, so
it defaults to "safe".

## The held-out real test did its job

The controlled MCC 0.546 alone would have read as a win. The mined-real + gold-core
held-outs caught the synthetic-memorization and prior-collapse. This is exactly
the failure mode Zakhar flagged ("will it just learn the template") — confirmed,
and caught by design, not shipped.

## Go/no-go answer

- Model path is **viable in principle** (the concept is learnable).
- Synthetic-only data is **NOT the fix** (no transfer + recall collapse).
- We now know precisely why, measured on 3 real test sets.

## Options for next

A. **Mixed anchor (cheap, ~$4):** re-train with synthetic XSS + a clean real
   general-triage anchor (the 31% learnable old rows / gold-core-style) to stop
   the prior-collapse. Final model-path test. If recall holds AND discrimination
   rises, the recipe is "synthetic concept + real anchor".
B. **Real snippet-sufficient pairs (hard):** solve extraction so data-source +
   sink + escape are all in-window for real code. Expensive; real code resists it
   (GPT-5.3 only 44% on mined).
C. **Accept the ceiling, pivot:** the 7B can't be a standalone real-code judge on
   this budget. Go tiered (7B ranks, frontier-agent confirms) + demand validation
   (the riskiest hypothesis, untouched, needs no compute).

Recommendation: A is the one cheap experiment left worth running as the decisive
model-path test. If A also fails to transfer, the standalone-model path is closed
and C is the honest move. Either way, demand validation does not depend on this.
