## Главное открытие — root cause v8.2 paranoia

**v8.2 train имел 64% дубликатов с конфликтующими лейблами.** Один и тот же
кусок кода появлялся до 20 раз в train с противоречивыми verdict'ами (TP
для одного CWE, FP для другого).

Причина: `prepare_cvefixes_triage.py` misclassification FP стратегия — для
80% FP брали `fixed_code` другой CVE row и подставляли наш CWE-label. Один и
тот же fixed_code мог попасть в:
- TP-pool своей CVE row
- FP-pool для CWE-89 misclass
- FP-pool для CWE-22 misclass
- ...

→ Тот же код, противоречивые лейблы. Градиент тянул verdict-токен в обе
стороны на идентичном входе. Модель математически не могла выучить ничего
кроме приближения к базовой частоте: **paranoia (default to TP) + collapsed
logprob gap**.

**Доказательство механизма**:
- v8.2 first-token gap median(p_tp|TP) - median(p_tp|FP) = 0.058 (collapsed)
- v8.3.0 (clean dedup train, тот же base, те же hyperparams): gap **0.175**
  на in-domain

Один-в-один как предсказал external reviewer без проверки данных. Чистый
mechanistic confirmation.

## Что **не** работает (failures и dead ends)

1. **Calibration trick на v8.2 SastBench (10.06.2026)** — потратили ~$1.40 на
   threshold sweep. Gap p_tp=0.058 слишком мал, sweep overfits на val noise,
   transfer val→test catastrophic (-0.011 MCC на test). Memory:
   `feedback_no_oracle_leak_in_calibration.md`.

2. **Per-language flip wedge (oracle ceiling vs honest CV)** — Захар поймал
   математику "MCC=-1 ⇒ flip → +1". Oracle ceiling выглядел +0.10 MCC,
   honest 5-fold CV дал **только +0.014**. ~7x раз inflation. Memory rule:
   калибровочные параметры обязаны выбираться на val/CV не на test.

3. **Sufficiency probe via model-proxy (Sonnet labeling)** — потратили
   ~$1.40 на killed mid-way probe + ~$1.30 на labeling. Результат: Sonnet
   verdict почти не меняется от добавления evidence packet (37 vs 36 TP из
   50). Frontier single-call **paranoid тоже** независимо от контекста. То
   есть evidence packet (Sprint 2) НЕ помогает на этой задаче.

4. **v5b-v7lite era** — все попытки масштабировать train или менять LoRA r
   без diversity sources давали F1 0.78-0.86 in-domain и BalAcc 0.50
   (рандом) на cross-project. Methodology > data scaling. Не помогало.

5. **D2A integration** — D2A на IBM DAX требует регистрации, не drop-in.
   Плюс C/C++ only, наш фокус web. Отложено.

6. **Cluster-CV per-slice calibration на v8.3.1** — после multi-source
   residual per-slice bias маленький, CV overfits на fold noise. CWE-79
   слайс flipnул с +0.05 на -0.275. Production: **default threshold 0.5**,
   per-slice calibration НЕ recommend.

## Что узнали методологически (для будущих iterations)

1. **Cluster bootstrap mandatory** для clustered eval (WeGIA = 30% SastBench
   cases). Case-level bootstrap underestimates variance. v8.2 headline 0.10
   с case CI [-0.01, +0.19] vs cluster CI [-0.04, +0.19] — узкий хвост
   справа маскировал реальную unstableness.

2. **Partial dumps в любом long-running скрипте** (правило от Захара). Мы
   потеряли $1.40 на probe который crash'нулся mid-way без записи partial.
   Все скрипты теперь пишут `.partial.json` каждые N items.

3. **Meta-check между experiments** — не auto-pilot pipeline. После
   labeling stage уже стало ясно что evidence не двигает фронтир; зря
   запустил probe.

4. **Smoke перед full** — после нескольких case'ов где prep упал на mismatch
   library version (trl 1.5.1 переименовал `max_seq_length` → `max_length`),
   стало правилом: 0.25 epoch smoke train перед full launch.

5. **Honest CI обязателен в pitch numbers** — point estimate всегда красивее
   чем cluster CI. Если CI пересекает 0, claim "лучше рандома" — fragile.
   v8.3.1 первый раз CI lower bound на 0 — статистическая значимость
   borderline.

## Тех wedge'и которые работали

1. **Hash-based code dedup with verdict awareness** (`prepare_v8_3_clean.py`)
   — единственный single fix который убрал главный problem. Effect size
   огромен (gap 0.058 → 0.175 на in-domain).

2. **Multi-source mix с source-tag** (`merge_v8_3_1_train.py`) — добавление
   CrossVul к clean CVEFixes дало second ⅓ of FAR reduction.

3. **Strict (code, verdict) uniqueness across sources** — в merge'е
   ловим case'ы где один и тот же код в обоих source'ах имеет разные
   verdicts. На сегодняшнем merge'е 0 таких, но gate важный для future
   multi-source.

4. **Anti-leakage по code SHA против всех eval files** — гарантия что
   train ↔ test code не пересекаются. 126 CrossVul rows пропущено по
   leak'у, 0 в test ↔ train overlap.

5. **Cluster bootstrap honest CI** — даёт реальную меру variance которую
   обычный bootstrap прячет.
